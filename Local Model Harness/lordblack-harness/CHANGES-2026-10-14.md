# LordBlack Harness — Security & Bug-Fix Pass, 2026-10-14

An independent code audit (backend + frontend) was run against v0.8.4 and all
major findings plus the highest-value mid-tier ones were fixed in this pass.
All 21 unit tests still pass, and the fixes were verified against a live
server instance.

---

## Major fixes (security)

### 1. XSS in chat markdown rendering — `frontend/js/markdown.js`
`inline()` rendered model output into `innerHTML` without HTML-escaping, so
any HTML in a model reply (or persisted localStorage history) executed in the
UI. Links were also injected into `href` unvalidated.
- **Fix:** `inline()` now escapes the text *first* (`esc()`), then applies
  code/bold/italic on the escaped text. Markdown links are only emitted when
  the URL is `http(s)://` or `mailto:`; anything else is shown as plain text.

### 2. Logs page was always visible — `frontend/css/pages.css`
`#page-logs { display: flex; }` (ID selector) outranked
`.page { display: none; }`, so the logs page overlaid the main area on every
page at all times.
- **Fix:** the hidden state is restated on the ID
  (`#page-logs { display: none; }` + `#page-logs.active { display: flex; }`).

### 3. Agent slug path traversal — `backend/agents.py`
A caller-supplied `slug` was used verbatim in file paths, so a slug like
`../../config` could write or delete JSON files anywhere on disk.
- **Fix:** `save_agent()` and `delete_agent()` now *always* re-derive the
  slug through `slugify()`; a caller-supplied slug can no longer contain path
  characters. Verified live: `../../config_TESTCANARY` is stored as
  `config-testcanary` inside `data/agents/`.

### 4. Permissive CORS on an unauthenticated localhost API — `backend/main.py`
`CORSMiddleware` with `allow_origins=["*"]` meant any website open in the
browser could call privileged routes (grant arbitrary folders, read granted
files, wipe memory, edit config).
- **Fix:** the CORS middleware was removed entirely. The UI is served
  same-origin and LAN clients open the server origin directly, so no CORS is
  needed. Verified live: no `Access-Control-Allow-*` headers are returned.

### 5. Tokenless hosted agents could leak private data — `backend/main.py`, `backend/agents.py`
A hosted agent without a bearer token was reachable by anything on the
network, and its tools included `memory_search` / `read_file` — an attacker
could ask the agent to read private data and repeat it in its answer.
- **Fix:** a `PRIVATE_TOOLS` set is defined in `agents.py`. When a hosted
  agent has no token, `/agents/{slug}/chat` now strips all private tools
  before running it (only `external_lookup` / `bluetooth_scan` remain).
  Token verification also now uses `secrets.compare_digest` (constant-time).

### 6. Embedded llama.cpp embeddings were permanently broken — `backend/providers/local.py`
`embed()` overwrote the `Llama.embed` *method* with `True` and then called
it, so every embed raised `TypeError` — and one failure downgraded the whole
memory system to keyword mode until restart.
- **Fix:** the method is looked up with `getattr(llama, "embed", None)` and
  only called if callable; the instance attribute is never overwritten.

## Major fixes (correctness)

### 7. Chat history duplicated on every workspace revisit — `frontend/js/workspace.js`
`loadChat()` never cleared `#chat-thread`, so every workspace → elsewhere →
workspace navigation rendered all bubbles again.
- **Fix:** the thread is cleared before replaying history, and `recentTrace()`
  runs only once per session (`traceLoaded` guard) so the Activity panel
  doesn't fill with duplicate entries either.

## Mid-tier fixes

- **Memory title wipe** — `backend/main.py`: a content-only
  `PUT /api/memory/documents/{id}` (no `title` field) used to blank the
  title and rename the file. It now keeps the existing title.
- **Settings "Test Connection" crash** — `frontend/js/settings.js`: clicked
  with zero runtimes configured it threw `TypeError` on `primary.id`; it now
  shows "no runtime configured" instead. Disconnect is guarded too.
- **Plaintext key fallback reported as encrypted** — `backend/config.py`:
  if `encrypt_secret` ever fell back to `plain:`, `key_storage_mode()` still
  reported "dpapi". It now returns `"plain"` when a fallback has occurred in
  this process or when a `plain:` key is found in the config on disk.
- **Slow SSE clients hung forever** — `backend/sysinfo.py`: when a stats
  subscriber's queue was full it was discarded from the subscriber set, but
  its stream kept awaiting forever. The sampler now drops the oldest sample
  and keeps the subscriber alive (stats are lossy by design).
- **`API.upload` masked real errors** — `frontend/js/api.js`: a non-JSON
  error response crashed with a JSON `SyntaxError`; it now falls back to
  status text like the normal request path.
- **`confirmModal` hung on backdrop/X dismissal** — `frontend/js/ui.js`:
  dismissing a confirm dialog via backdrop or the ✕ button never resolved
  the promise, leaving awaiting code (e.g. pending deletes) stuck. It now
  resolves `false`.
- **Modal titles were unescaped** — `frontend/js/ui.js`: `UI.modal` injected
  the raw `title` (used with model-proposed file paths in the diff/preview
  dialogs) into HTML; it is now escaped, as are `confirmModal` text and
  button label.
- **`run.bat` ignored pip failures** — `run.bat`: the `.venv\.installed`
  marker was written even when `pip install` failed, so a broken first run
  was never retried. It now aborts with a clear message on failure.
